## 1. 设计结论

新增独立的「星语」板块，以完整塔罗仪式引导用户整理问题，再由 AI 结合牌面、牌位与用户背景给出解读，并在同一聊天中持续追问。历史保存在设备，离线仍能抽牌、查看牌义和回看记录。

第一版采用 78 张 RWS 体系、六个方向、六套固定牌阵，默认启用正逆位，不提供切换设置。客户端负责抽牌和持久化；notify-api 内新增受设备签名保护的塔罗 AI 路由，服务端持有模型密钥和提示词。AI 只分析已经确定的牌，不参与选择、替换或补抽卡牌。

这是一项象征解读与自我探索功能。产品保留仪式感，但不显示「命运已注定」「准确率」「购买成功概率」等无依据结论，不用恐吓和反复重抽制造依赖。

## 2. 入口与信息架构

首版保留现有「星球 / 写日记 / 设置」底部结构，在星球右上工具区新增带星形图标的「星语」入口，优先级低于日记。它与日期搜索、随机回望共享安全区，不覆盖可点击星体。设置中增设「星语塔罗」行作为第二入口。

理由：当前悬浮导航围绕中央写日记构图；首版增加四个不对称栏目会牵动主页动效与肌肉记忆。若后续星语使用频率证明需要常驻入口，再单独评审全局导航，而不在本次扩展中顺带重做。

| 路由 | 页面 | 行为 |
| --- | --- | --- |
| /tarot | 星语首页 | 方向选择、继续未完成记录、最近历史、历史入口 |
| /tarot/new | 问题页 | 问题、二选一选项、可折叠补充背景；牌阵随方向固定，默认启用正逆位 |
| /tarot/:id/ritual | 仪式页 | 洗牌、切牌、选牌和揭示，内部阶段不逐项压入路由栈 |
| /tarot/:id/chat | 对话页 | 固定牌阵摘要、自动首解或本地牌义、追问、个人笔记 |
| /tarot/history | 历史页 | 本地搜索、方向/收藏筛选、继续草稿、删除 |

所有塔罗页面采用沉浸式子页面，隐藏原底栏；必须同步收紧 App.vue 的 showTabBar 判断。使用独立路由 meta，例如 hideBottomNav，而不持续堆叠字符串判断。首页返回星球，内部返回遵守 Ionic 页面栈；深链接直接打开时回退到 /tarot。

## 3. 塔罗规则与产品约定

常见塔罗牌组有 78 张：22 张大阿卡纳、56 张小阿卡纳；小阿卡纳包括权杖、圣杯、宝剑、星币四组，每组 14 张。采用 RWS 编号：力量 VIII、正义 XI；愚者为 0。[S1][S2]

洗牌、切牌、摆放与解读是常见实践，但具体切法、是否读逆位和牌阵含义存在不同方法；本产品的下面规则是明确的数字化约定，不宣称唯一正统。学习资料将切牌作为整理牌组的结束步骤，也说明逆位不必等同坏结果。[S3][S4]

### 3.1 六个方向与固定牌阵

以下牌位为本产品为日常问题编排的模板，并非直接照搬某个传统标准牌阵。每个方向首版只有一个推荐牌阵；卡片点击前即展示张数、结构和耗时预期。

| 方向 / scenarioId | spreadId@version | 张数 / 牌位顺序 | 输入重点 |
| --- | --- | --- | --- |
| 购物决策 / shopping | purchase-4@1 | 真实需要 → 可能收获 → 潜在代价 → 行动建议 | 想买什么、可选价格、预算感受、已有替代品 |
| 二选一 / choice | choice-5@1 | 当下处境 → A 的助力 → A 的挑战 → B 的助力 → B 的挑战 | 必填 A、B，明确比较标准；两者均有价值与代价 |
| 近期状态 / self | reflection-3@1 | 此刻状态 → 忽略的线索 → 下一步行动 | 想梳理的状态或困惑 |
| 关系相处 / relationship | connection-3@1 | 我的状态 → 互动模式 → 我能做什么 | 描述自己可观察的互动，不声称读懂他人秘密 |
| 工作学业 / growth | growth-4@1 | 当前处境 → 主要阻碍 → 可用资源 → 下一步行动 | 一个具体任务、选择或近期目标 |
| 一张指引 / guidance | guidance-1@1 | 此刻提醒 | 一个简短问题或意图 |

不预设未来必然结果。购物解读应比较需要、使用频率、预算和替代方案；二选一对称分析 A/B，再建议下一步验证，不把「正位多」换算成分数或强行宣布获胜项。

二选一的视觉摆位：当下处境置顶居中，左列为 A 助力/A 挑战，右列为 B 助力/B 挑战。用户可选择任意空牌位开始抽牌，显示与阅读仍按表中稳定序号组织。购物/工作用两列两行，状态/关系三张横排，窄屏可换两行但不改变语义顺序。布局统一保存归一化坐标与可访问阅读顺序。

### 3.2 正逆位

- 默认启用正逆位，问题页不展示牌阵设置或逆位开关。已有抽牌和历史记录保留原来的朝向。
- 每张卡在洗牌阶段独立产生一次 50% 逆位标记。50% 是本产品模拟约定，不是对实体塔罗的统计结论。
- 洗牌结束后卡牌与方向绑定，切牌只移动牌，选牌和翻牌不会再随机方向。
- 逆位卡面旋转 180°，卡名、牌位及「逆位」标签保持正向；无障碍读出完整信息。
- 逆位结合阻滞、内化、过度或待调整等角度理解，不自动当成正位反义词。不可把死神、高塔、恶魔直译为现实灾祸。[S4]

## 4. 端到端交互

### 4.1 首页：把一个问题放在星光里

页头「星语」配一行轻提示「换个角度，听听心里的声音」。主内容是六个方向，购物与二选一优先，显示具体用途；底部简短说明「塔罗提供思考角度，选择仍由你决定」。

存在草稿时显示「上次的问题还在，继续看看吧」，展示方向、问题前一行与阶段。支持多个历史草稿，但首页只突出最近一条；新建不会覆盖旧草稿。历史入口始终可见，空状态为「这里会收好你问过的每一个问题」。

### 4.2 问题页：先问清楚

主输入「你想问些什么？」必填 5–800 个 Unicode 码点，纯空白无效；提示具体问题优于抽象断言。二选一显示 A/B 输入，各 1–100 字且归一化去空白后不同。购物可补物品、价格、预算与已有替代品；金额均选填，币种明确，纯本机保存至用户使用 AI 时才发送。

补充背景最多 1,200 字；所有方向可选「希望关注的时间范围」，只作为上下文，不代表预测期限。自动保存草稿，失败时明确提示未保存，并停留当前页，不进入不可恢复的仪式阶段。

页面以单一问题输入区为视觉中心：顶部只显示方向与「你想问些什么？」，输入区底部显示字数；二选一的 A/B 必填项直接展示。补充背景默认折叠，收起时显示填写状态。不展示牌阵设置，牌阵随方向固定，正逆位默认启用。底部主按钮「去洗牌」保持可达。准备进入仪式时锁定问题、选项和牌阵；返回修改将废弃本次未完成抽牌并生成新牌组，已翻过牌的记录则保留为独立历史，不能原地改题。

### 4.3 洗牌：可以慢一点

页面仅保留「洗牌」标题、散铺牌桌和必要按钮。卡牌背面散乱铺开，点击「开始洗牌」后在桌面范围内推散、绕动、交换位置，避免叠放牌堆式洗牌。原型以 32 张可视卡背表现 78 张完整牌组；可视数量不影响真实牌组数量。一次完整洗牌提交一次新牌序，动效中的每一帧不更新随机结果。完成一轮即可继续，不设强制三次或倒计时；可再次洗牌。

默认散洗动效约 1.8 秒，依次推散、交错、回旋，洗完仍保持散铺。完成前仅显示「开始洗牌」；完成后主按钮变为「去切牌」，「再洗一次」作为轻量次操作。仅在点击「去切牌」后将散牌收拢成牌堆，再衔接切牌页，过渡约 1.2 秒。减少动态效果时缩短动画。动效期间锁定导航和重复操作，已经提交的牌序保持。

### 4.4 切牌：轻点牌堆完成

默认展示合并的牌堆，点击牌堆或「切牌」按钮才分开、交错交换并合并，动效约 1.05 秒，完成后仍停留本页。原型每次在 18–60 之间随机选择切点 k，将牌组 D[k..77] 放到 D[0..k-1] 前面，不展示切点滑块。页头提供「‹ 洗牌」返回入口；「切牌 / 再切一次」按钮放在牌堆下方、「去抽牌」按钮上方。至少完成一次切牌才启用下一步。

抽牌开始前可以再次切牌，每次基于上次提交的牌序旋转，正逆位随卡移动。返回洗牌后重新洗牌会清除尚未使用的切牌结果，需再次切牌；洗切返回均保留问题。选定任何一张牌后，仍可返回查看洗切页面，但禁用重新洗牌和切牌，已抽卡与剩余牌序保持不变。

### 4.5 抽牌：抽到的，就是选中的

抽牌页仅展示虚线牌位、返回切牌入口、完成数量及翻牌按钮，移除常驻下方牌带和「帮我抽完」。所有牌位可独立点击，允许按用户选择的顺序填充；抽取时间顺序与牌位顺序分开保存。牌位布局尽量在一个手机屏幕内完成，二选一保持「上方当下处境、左 A/右 B」的对应关系。

点击空牌位，进入整页圆环牌桌，标题显示当前目标牌位；不使用半屏弹出框、位置滑块或放大按钮。牌组首尾闭合，初始第 1 与第 78 号牌相邻；圆心偏向屏幕右侧，呈现斜向扇面。支持单指滑动旋转与松手惯性、双指连续缩放，缩放范围 0.8–1.8 倍，任意尺寸均可直接选牌。桌面支持滚轮旋转、Ctrl 加滚轮缩放、方向键及加减键。卡背顶部显示从切牌后牌序生成的 1–78 编号，抽走后其余牌不重新编号；编号不暴露卡牌身份或正逆位。滑动时复用卡片节点，仅更新圆环位置与角度。

选中后，在单个本地事务中保存卡牌 ID、方向、原始槽位、牌位和实际抽取次序，再将所选卡抬起、旋正、飞入目标虚线框，约 680ms 后定格背面；飞行中隐藏目标卡背，避免显示两张。选中牌从剩余组移除，填充牌位禁止再次点击；事务失败不消耗牌，连点和多指操作由提交锁拦截。拖动超过 7px 只浏览，不抽卡。缩放、返回牌阵不重新洗牌；返回后可选另一空牌位继续。

未抽满时所有已选牌均为背面，翻牌按钮禁用；抽满后启用「翻开我的牌」，一次锁定完整结果并依次揭示。每张翻开约 550ms，相邻错开 95ms；打开历史不重复播放。不提供自动补齐、换牌、撤销偷看或按牌义调整概率。

### 4.6 翻牌：先认识它们

沿用抽牌页的紧凑牌位结构，所有卡面、卡名、牌位、方向及进入聊天按钮优先完整放在一屏。二选一五张采用三排，购物/工作四张采用两排，三张横排；高度根据可用空间缩放。移除牌阵下方逐牌解释列表与重复提示文案，点击单牌查看详情。

点击任意牌面打开详情弹层，展示较大卡面、正逆位、牌位、关键词、基础牌义、当前方向的解释及结合牌位的思考提示。弹层单独滚动，关闭回到原牌阵；不触发网络或 AI 请求。正式卡义需逐卡人工审校，原型内的几何图和解释内容均为交互示例。

结果先持久化，再进入对话页。若用户此前已同意当前 AI 数据说明，对话页自动创建首解请求；首次使用则在对话页内显示数据说明与「让 AI 解读」按钮，确认后自动开始。拒绝或离线时仍能查看全部牌面和本地牌义。

### 4.7 对话页：先给完整解读，再聊具体问题

顶部固定可折叠的本次问题、方向和牌阵缩略图。第一条由 AI 主动给出综合解读，按「整体线索 → 逐牌说明 → 问题建议 → 可执行的一小步」组织。用户无需再发送「请解读」。

输入框占安全区上方，支持 1–1,000 字追问，生成时显示「停止」且禁止并行发送。流式内容持续显示；用户向上滚动时不强制拉回底部，显示「有新回复」入口。快捷追问为本地固定模板，例如「为什么这张牌在这个位置？」「我可以先做哪一步？」；点击只填入输入框，用户发送后才联网。

只沿用当前牌阵追问；「再问一个问题」建立新记录。首版不支持追问补牌、不编辑已发送消息、不重新生成多个答案分支；若用户停止或错误中断，可明确发起新请求，保留原有不完整答复并标注。

个人笔记是独立本地输入，不自动进入 AI 上下文。首解建议 600–900 中文字、追问 200–500 字；这是写作目标，服务端使用 token 硬上限控制消耗。

### 4.8 历史：回得去，也接得上

本机分页展示，每页 20 条，按 updatedAt 降序和 ID 作稳定次排序。卡片包含方向、问题摘要、创建时间、卡名缩略与状态；最新追问会更新时间，创建日期始终保留。筛选支持方向、收藏、未完成，搜索问题/选项/个人笔记，首版不索引长篇聊天。

未完成记录恢复至最近有效阶段；已揭示记录进入原对话。打开历史和搜索均不联网，恢复聊天也不会重新生成首解。只在用户选择恢复一条状态不确定的 AI 请求时查询该请求结果。

支持收藏/取消、编辑最多 2,000 字的个人笔记、重命名最多 80 字的显示标题、删除与清空塔罗记录。显示标题独立于原始问题，改标题不能改历史抽牌和 AI 上下文。删除有明确确认，随后本地硬删除会话、抽牌与消息；取消请求，晚到回包不得复活记录。服务器短期恢复缓存的清理见接口规格。首版不包含塔罗云备份或独立导出，卸载会丢失本机记录，说明放在历史管理页。

## 5. 状态与恢复规则

业务阶段和 AI 请求状态分别建模，不能用一个 status 同时表示「已抽完」与「网络失败」。

~~~text
会话：draft → shuffling → cutting → drawing → revealed
                                      ↓          ↓
                                 保存退出      对话与笔记

每次请求：prepared → sending → streaming → completed
                         ↘ failed / interrupted / unknown
~~~

| 事件 | 确定行为 |
| --- | --- |
| 任意阶段返回/锁屏/进程结束 | 已提交阶段保持；动画不是事实来源；输入按防抖及失焦落盘 |
| 洗牌动效中退出 | 使用最后一次完成提交的 deckOrder；不根据动效重新生成 |
| 抽牌事务中崩溃 | 事务要么全部提交，要么完全不提交；重开读取唯一有效状态 |
| 抽满未翻牌时退出 | 恢复原卡；允许继续揭示，禁止重抽覆盖 |
| 结果已存但 AI 未请求 | 显示牌阵与开始解读入口；满足同意条件才自动首解 |
| 流式中退出页面 | 尽力取消网络，保留已收到文本并标记未完成；不后台悄悄续费 |
| 网络恢复 | 不自动提交此前从未发送的私人问题；用户明确继续后再发 |
| 首解失败/配额耗尽 | 原牌阵保持，提供离线牌义；可在允许时继续请求 |
| 撤回 AI 同意 | 停止当前请求、后续不上传；已有本地历史保留，缓存删除独立处理 |

## 6. 视觉与动效规范

方向为「午夜天文手札」：延续星球的深色宇宙背景，以少量旧金色线条、月相、纸张式卡面建立塔罗的辨识度。本轮按用户对 Quin 的偏好减少装饰和操作：保留大留白、安静的背景与卡牌主体，移除仪式英文阶段名、进度条和重复返回按钮，每页突出一个主要动作。仅借鉴用户描述的简洁感，未复刻其卡面或未经实测的具体手势。

| Token | 默认建议 | 用途 |
| --- | --- | --- |
| --tarot-bg | #131F29 | 午夜蓝绿底色 |
| --tarot-surface | #1B2B35 | 抽屉和输入区 |
| --tarot-ink | #EEE9DE | 正文 |
| --tarot-muted | #A3B1B5 | 辅助信息，正式版校验对比度 |
| --tarot-gold | #D2BB8E | 牌框、阶段、主按钮 |

这些是模块语义变量；通过 getThemePresentation 映射三套现有主题，不能全局硬编码并绕过主题中心。牌组内容与 App 主题独立：切换主题改变桌面与控件，不替换历史记录使用的牌组和牌图。

标题采用有中文衬线气质的字体，正文沿用 App 的可读字体栈；如引入外部字体须本地打包并记录许可，原型使用本机可用宋体/雅黑，不外链字体。卡牌比例建议 2:3，卡背统一月环几何图案，正逆位只转卡画。

交互目标至少 44×44 CSS 像素，正文不小于 15px；主要按钮对比度至少 4.5:1，控件边界至少 3:1。支持 320px 宽屏、字体放大、横屏、键盘与 TalkBack；所有动作有按钮替代拖拽，顺序与牌位编号一致。

旋转/位移使用 transform、opacity；不为 78 张牌同时创建复杂阴影或独立 Canvas。首版 DOM/CSS 足够，需粒子时再用单层已有 Canvas 思路；不引入 Three.js。关闭页面或进入后台暂停动画，prefers-reduced-motion 时取消翻飞和漂移。音效默认关，触感跟随用户偏好且提供关闭。

## 7. AI 解读设计

### 7.1 请求与模型选择

App → notify-api 的 /v1/tarot 下专用路由 → 服务端模型适配器 → 文本模型。只需文本，无须识别图片：服务器根据稳定 cardId 取受控牌义，与问题、牌位、方向合成上下文。服务商密钥、系统提示词和调用地址全部由服务器控制。

建议先做一个可配置的 DeepSeek Chat Completions 适配器验证中文表达与流式链路；其官方接口支持 messages 与 stream。模型 ID 在实施时按账号实际可用列表配置，设计不锁死某个可能更名的型号，不使用旧教程中的名称直接上线。[S9]

是否关闭思考、温度与 token 参数由所选模型的实际能力决定；首版目标为低等待时间和稳定解读，内部推理不展示给用户。首版单供应商，失败不自动切换另一家，避免额外数据接收方与重复计费。

### 7.2 上下文顺序

1. 服务端版本化 system prompt：角色、规则、表达边界和输出格式。
2. 服务端受控牌阵和牌义：牌位含义、卡名、正逆位关键词与基础说明。
3. 本次用户问题、结构化选项与背景，作为明确标记的不可信数据。
4. 首次完整解读、最近若干轮完整对话、当前追问；具体裁剪见接口规格。

用户输入不能指定 system/developer 角色、模型、外部 URL 或 tools。聊天无需联网搜索、日记工具、邮箱工具或文件读取。防提示词注入依靠权限隔离、字段校验与受控上下文，不能把一段「忽略恶意指令」当作完整防线。

### 7.3 首解提示词示意

~~~text
你是拾光笺的星语解读助手，温柔、具体、平等地帮助用户思考。
给定的卡牌、方向和牌位已经确定。只解读它们，不抽牌、不替换、不补牌。
结合用户问题说明每张牌在该位置的意义，再分析牌与牌之间的联系。
区分用户明确提供的事实与由象征产生的可能解读；不编造个人经历。
逆位不等于坏事；涉及死神、高塔、恶魔时解释其象征，不预言灾祸。
二选一必须分别分析 A 与 B 的助力和挑战，不计算伪概率。
购物问题关注需要、预算、代价和可验证的下一步，不施压消费。
不把塔罗当作医学诊断、投资保证或确定的第三方心理事实。
如遇现实中的紧急安全问题，优先回应现实需求，不继续神秘化解释。
用简体中文；避免宿命论和过度亲密。不要声称知道未来或有超自然能力。
依次写：整体线索、逐牌解读、回到你的问题、可以试的一小步。
~~~

只生成展示给用户的答复，不展示内部推理。首次 600–900 字，追问 200–500 字，最多一个有帮助的反问，不强迫用户提供更多隐私。现实信息不足时给出条件化建议，例如「如果这笔预算会影响日常开支，可以先等一等」，而不是直接假设用户经济情况。

### 7.4 品质门槛

上线前准备不少于 30 条人工评审案例，覆盖六个方向、正逆位、全大牌、无大牌、模糊问题、重复追问和危险断言诱导。核对卡名/方向/牌位准确率 100%，不编造额外卡牌；A/B 对称分析，建议可执行，不输出伪概率、必然灾祸或未经提供的用户事实。离线基础牌义由人工审校，不能直接把未经校对的翻译当最终内容。

## 8. 数据边界与用户说明

| 数据 | 本机长期保存 | notify-api | 模型服务商 |
| --- | --- | --- | --- |
| 问题、选项、背景 | 是 | 当前请求处理期间读取，不做输入正文落库 | 在用户同意后发送 |
| 抽牌与牌阵 | 是，固定快照 | 校验 ID 并补充受控牌义 | 随解读请求发送 |
| 对话文本 | 是 | 当前上下文临时处理；完整回复加密恢复缓存最长 24 小时有效 | 当前解读必要上下文 |
| 个人笔记、收藏 | 是 | 不发送 | 不发送 |
| 原有日记和图片 | 沿用原机制 | 塔罗路由无读取与转发能力 | 不发送 |
| 设备身份、额度、请求状态 | 必要标识 | 独立 AI 元数据表 | 不发送真实设备 ID/邮箱 |

首次使用 AI 的文案建议：

> AI 会收到这次的问题、你填写的背景、抽到的牌和本次必要的聊天内容，通过拾光笺服务向模型服务商请求解读。历史主要保存在本机；服务端会短暂加密缓存完整回复，方便断线后取回。个人笔记和其他日记不会发送。

按钮「同意并开始解读」与「先看本地牌义」，可展开查看当前服务商名称、实际数据处理政策和 24 小时缓存说明。记录同意版本、服务商标识与时间；更换服务商或扩大数据范围需更新同意版本。每次发送追问属于同一已说明用途，无需反复弹窗。

在「设置 → 星语塔罗 → AI 解读与数据」中查看服务商与说明、撤回同意和清理恢复缓存；「历史管理」中管理本机记录。通知邮箱的开关不作为塔罗开关。初次进入本地塔罗无须同意 AI 上传，选择使用在线解读时才出现数据说明。

不能宣称「AI 数据从不出设备」或保证模型商零留存；留存情况以上线时所选服务商、账号协议及配置核实为准。服务器缓存使用独立 AES-GCM 密钥和随机 IV，不写明文到日志；其删除、备份窗口与密钥轮换在接口规格中说明。

## 9. 工程落点

~~~text
diary-app/src/
  features/tarot/
    pages/       Home、Question、Ritual、Chat、History
    components/  TarotCard、ScatterTable、CutDeck、FanPicker、SpreadBoard、CardSheet、ChatComposer
    stores/      tarotStore、tarotChatStore
    domain/      types、spreads、deckEngine、stateMachine、contextBuilder
    services/    tarotAiClient、tarotConsent
    repositories/tarotRepository、localTarotRepository、sqliteTarotRepository
    data/        deck manifest、中文牌义、固定牌阵
diary-app/public/tarot/decks/<deckId>/<version>/
  manifest.json、卡背、78 张压缩牌图、LICENSE

external-api/services/notify-api/src/tarot/
  routes、schema、prompt、catalog、aiProvider、requestStore、quota、resultCache
~~~

页面只依赖 Store/Use Case；随机引擎不依赖 UI、网络或模型。复用现有设备身份模块但抽取可共享的签名传输，避免将 AI 流式响应塞进现有 JSON 邮件客户端。现有 15 秒 JSON 超时不能直接用于 AI；独立配置见接口规格。

App 与服务端各自携带同版本 catalog；通过固定数据包和校验摘要同步，不引入新的运行时共享包。API 返回有效版本，旧 catalog 至少保留至所有支持的 App 版本退役；不兼容时拒绝新 AI 请求但仍可读本地历史。服务器不接收客户端自定义牌义和牌位说明。

卡牌 manifest 至少包含 deckId、version、catalogVersion、cardId、nameZh、nameEn、arcana、suit、rank、imagePath、upright、reversed、source、license。历史保存卡名/关键词/牌位快照和内容版本；卡图引用相对资源 ID，旧版本不能原位替换。图加载失败用卡名和几何占位图兜底，AI 按 ID 解析不受影响。

浏览器正式塔罗存储建议 IndexedDB，避免聊天文本快速耗尽 LocalStorage；通过 Repository 隔离，与现有日记存储保持互不干扰。原型为演示使用独立 LocalStorage 键，不处理真实 AI 数据；生产 Android 使用同库 V5 新表。

原型为了便于直接打开，使用 DOM/CSS、LocalStorage 和本地模拟回复；不包含正式牌图、生产 AI、真实设备签名、SQLite 迁移、网络恢复缓存、虚拟化牌带及三主题适配。这些实施要求以本设计和接口规格为准。原有 App 功能与线上服务未在本次修改。

原型样式现独立放在 `prototype.css`，与 `prototype.html` 保持同目录即可打开；无外部字体、图片或动画库依赖。本轮只调整此原型及设计说明，未接入 App 页面或 notify-api。

### 1.1 交互修订验收

- 散铺洗牌，切牌页返回洗牌，切牌操作与下一步分开，切点调整后要求重新提交。
- 在五张牌阵中先选第五牌位，再选第一牌位；放大和普通状态均能选牌，卡飞入指定位置后禁止重抽。
- 扇面实际横拖已验证为浏览，不误抽；剩余编号保留被抽卡的缺口，位置滑块支持浏览至完整牌组。
- 刷新后恢复原先抽到的第五张牌；返回切牌保持结果，洗切操作锁定。
- 五张牌的抽牌页和翻牌页在 320×700 下内容高度等于容器高度，无横向溢出；390×844 下检查扇面及放大状态。
- 翻牌页没有逐牌解释列表；点击单牌出现基础牌义、方向和牌位相关详情，关闭回到原牌阵。

### 1.2 视觉与连续动效修订验收

- 减少英文阶段信息、边框和重复说明，保留午夜蓝、低饱和旧金与纸色卡面；每页只突出一个主要操作。
- 实测散铺洗牌到收拢，再进入切牌；切点可从 39 调到 40 后提交，动效期间导航和重复操作禁用。
- 五张牌阵先填第五牌位，再填第一牌位；放大状态点选和普通状态键盘选牌均成功，卡牌抬起后落入指定牌位。
- 在 320×700 下实际横拖扇面，中心编号改变、剩余牌数不变、没有误选；抽走的编号不被补齐。
- 选定一张后刷新，从首页恢复仍只填充原第五牌位；返回切牌后切牌与切点禁用。抽满后揭示，单牌详情可打开和关闭。
- 在 320×700 下检查三张横排、四张两行和五张三行：主区域 clientHeight 与 scrollHeight 均为 615px，页面宽度与滚动宽度均为 320px。390×844 下检查普通及放大扇面、五张牌阵和翻牌页。
- 历史中旧购物记录可恢复，原有模拟对话、收藏和笔记保留；进入新记录的模拟解读正常。浏览器检查未发现控制台错误，内联脚本语法与本地样式引用校验通过。
- 以上是桌面浏览器手机视口验收，未代替 Android 真机、TalkBack、低性能设备或真实 AI 联调验收。

### 1.3 简化交互与输入页修订

- 当前交互采用散洗后停留、进入切牌时收牌、合并牌堆点击切牌、整页闭合圆环抽牌及双指连续缩放；取代 1.1 / 1.2 的切点滑块、半屏扇面和缩放按钮。
- 问题页聚焦主输入，二选一保留 A/B 输入，补充背景默认折叠；移除牌阵设置，默认启用正逆位。已有抽牌与历史朝向保持不变。
- 本轮已验证问题输入、字数显示、背景折叠与填写状态、二选一输入和进入洗牌流程；390×844 下普通问题页无内容溢出。移除设置后再次验证输入与草稿保存，内联脚本语法检查通过。
- 1.1 / 1.2 验证记录保留供追溯，不代表当前版本仍包含旧控件；当前版本未重新执行完整圆环抽牌、双指手势与 Android 真机验收。
